# M0 Data and Environment Foundation

This milestone prepares public smoke/eval data for the first multi-environment RL
baseline. The scope covers plan §7 families that have public-data fits today:
search (single-hop + multi-hop), coding, terminal basics, short SWE patch
supervision, general tool calling (single-turn + multi-turn), tool-call repair
negatives, structured JSON output, and reasoning (grade-school + competition).
Each dataset is tagged with its milestone usage, license, source revision,
reward type, contamination notes, and explicit `contamination_against` targets
in `data_registry.yaml`.

[^1]: `hotpotqa/hotpot_qa` ships a custom Hugging Face loader script that
    `datasets>=2.16` will refuse to execute unless `trust_remote_code: true`
    is set explicitly on the spec. The registry opts in for this source; the
    pinned `hf_revision` is the only guarantee on which loader code runs.
    Bumping the revision (or accepting a moved revision) effectively
    re-authorizes whatever Python the upstream loader contains.

## Run

Downloads must happen on the local CPU workspace first. The output directory below
is on the shared mount and can then be reused from the `NemTron` node.

```bash
source /work-agents/.venv/bin/activate
python src/nemotron/recipes/super3/milestones/m0_data_env/prepare_m0_assets.py \
  --output-dir /mnt/3fs/data/lei.song/nemotron/m0_data_env_foundation/smoke-20260516 \
  --max-train-per-dataset 100 \
  --max-val-per-dataset 25
```

Use `--overwrite` only to replace files generated by this script at the same
target path. With `--overwrite`, the script also deletes stale per-environment
sub-directories that the current registry no longer references (e.g. files
left behind from an earlier registry with extra envs) — `cleanup_stale_split_files`
removes anything matching `<output-dir>/<env>/*-split.jsonl` whose env id is
not in the currently selected dataset list. Without `--overwrite` the script
never deletes existing directories and refuses to start when targets exist.

## Health Check and Baseline

After data generation, run the offline health check on `NemTron` or another
execution node that can see the shared output directory. The command validates
row counts, required JSONL fields, and verifier smoke behavior. The built-in
oracle baseline is only a wiring check for reward environments; it is not a
model quality number.

```bash
python src/nemotron/recipes/super3/milestones/m0_data_env/run_m0_health_baseline.py \
  --input-dir /mnt/3fs/data/lei.song/nemotron/m0_data_env_foundation/smoke-20260516 \
  --best-k 2
```

Outputs are written under `<input-dir>/health_baseline/`:

```text
health_baseline/
├── health_baseline_report.json
└── health_baseline_report.md
```

## JSONL Contract

Each record is NeMo-Gym-compatible and keeps the fields used by the existing
Nemotron RL data transforms:

```json
{
  "environment": "math_reasoning_numeric",
  "milestone": "M0",
  "use_stage": ["M0 data_env_foundation", "M1 RLVR math/reasoning smoke"],
  "question": "Janet has 3 apples...",
  "expected_answer": "42",
  "responses_create_params": {
    "input": [
      {"role": "system", "content": "You are a helpful reasoning assistant."},
      {"role": "user", "content": "Janet has 3 apples..."}
    ],
    "tools": []
  },
  "reward_config": {
    "verifier": "normalized_numeric_exact_match",
    "max_score": 1.0
  },
  "extra_env_info": {},
  "metadata": {
    "source_dataset": "openai/gsm8k",
    "license": "mit",
    "data_stage": "M0"
  }
}
```
